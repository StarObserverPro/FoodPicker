# 聊天生图的创意库

本页只说明可复用的文字材料与选取规则。聊天接口、结构化计划、请求限额和出图参数以同目录中的实现文档为准。

## 库提供方向，模型完成场景

`play/library.mjs` 包含 14 种绘画风格、12 种错配方向和 8 种气氛。库里没有固定菜品名单，也没有把某句话映射成某张图。每个方向只是告诉文字模型：往哪类视觉关系上想、至少要说清什么、常见的失误是什么。

`selectLibraryDirections(seed)` 用可复现的本地抽样返回 3 种风格、4 种错配和 3 种气氛候选，避免每次把整库塞进提示词。调用方仍应让文字模型根据聊天选用、细化这些方向。候选条目的示例是解释方向的例子，不是需要复述的答案；模型应更换食物、道具和连接方式，只保留适合当前聊天的关系。

实际构思顺序为：

1. 从对话中找明确的食欲、食材、口味或现实限制；没有这些线索时，再用当下情境扩大猜测。
2. 选一种真实、可辨认的食物。语言和场所可以影响初始搜索范围，但不能据此给用户判定国籍、人格或长期偏好。
3. 把一个聊天细节变成视觉桥梁，例如“开车”对应引擎盖的开合，“等电梯”对应层叠和滑出。
4. 用一个主要错配完成具体场景。必要时加一个不争抢注意力的呼应，不再堆第二套互不相干的世界观。
5. 用一种主要媒介、清楚的主体关系和有限的色彩把场景画出来。气氛词应变成可见线索；“梦境”“超自然”不替代场景描述。

最终提示词的语序不必等同于这个构思顺序。它可以先用一句短媒介说明限定画法，但食物、嫁接位置和空间关系必须紧接着写清楚。对于结构嫁接、空间接缝等容易失去关系的方向，关系本身应占据开头的完整句子。任何媒介词都不能把主错配挤到长串形容词之后。

## 数据契约

| 导出 | 关键字段 | 用法 |
| --- | --- | --- |
| `STYLE_LIBRARY` | `id`, `label`, `medium`, `rendering`, `palette`, `detailPolicy` | 一个主媒介、一套构形方式和微细节约束；英文片段可直接用于编译提示词。 |
| `MISMATCH_LIBRARY` | `id`, `label`, `direction`, `bridgeRequirement`, `avoid`, `example` | 定义错配机制；模型必须补上可见关系及聊天依据。 |
| `ATMOSPHERE_LIBRARY` | `id`, `label`, `direction`, `visibleCue` | 一种气氛及其可见表现；具体光线仍要与主场景协调。 |
| `selectLibraryDirections(seed)` | `{styles, mismatches, atmospheres}` | 稳定抽取 3 / 4 / 3 个候选；不决定食物、不生成最终场景。 |
| `OPENERS` | `{id, text, topic}[]` | 240 条原创中文静态开场句；12 个话题，各 20 条。 |
| `chooseOpener({seenIds, random})` | `{id, text, topic}` | 从未见过的开场句中选一条；全部见过后重新开始。 |

全部导出均为零依赖 ESM，可由浏览器或服务端导入。各条目与数组冻结，调用方需要修改时先复制。ID 是程序引用，不应直接当成产品文案显示。

`chooseOpener` 不保存浏览器状态。调用方负责把已展示的 ID 留在当前浏览会话或本地存储，并在开新一轮时清空历史。它不发网络请求，不读时间，也不会在页面刚打开时调用模型。开场的正文和用户回复都应进入后续对话，以免用户回答“第二个”时失去上下文。

## 八个构思例子

这些是说明选择过程的例子，不是用户性格分类表，更不是固定触发规则。真实实现还要遵守用户已说出的忌口和不想吃的东西。

| 用户提供的线索 | 可猜的真实食物 | 视觉桥梁与主要错配 | 留给模型发挥的部分 |
| --- | --- | --- | --- |
| “开了几个小时车，想吃个汉堡。” | 汉堡 | 引擎盖的开合与面包夹层重合；上层面包直接成为小车引擎盖，肉饼夹在盖与车身之间。 | 车的轮廓、颜色、停车处；不用指定品牌。 |
| “刚把阳台收拾完，买了个花盆。” | 蛋包饭 | 蛋皮的包裹与盆沿的承托相接；干净花盆盛着整份蛋包饭，酱汁只在食物上。 | 花盆形状、一个植物轮廓的影子；不要把土放进饭里。 |
| “一直等电梯，又赶不上下一班。” | 千层面 | 食物层叠与电梯楼层对应；一层千层面从整体中像电梯轿厢一样滑出。 | 观察角度和简单背景；不用数字楼层或字幕解释。 |
| “今天环球影城玩得很尽兴，还想继续逛。” | 塔可或其他用户可接受的新口味 | 探索经历扩大食物范围，弧形饼壳借作一段游乐轨道，馅料仍能辨认。 | 轨道的小幅起伏、开放天空；不照搬园区角色或标志。 |
| “太吵了，想吃点辣的但不想再听见人说话。” | 红油面 | 听觉与面条节律相接；面条绕成一圈安静的唱片，筷子处在唱针的位置。 | 红油色块与唱片沟槽的简化程度；不需要真的画出声音文字。 |
| “终于把那份表填完了，没什么大事，就是开心。” | 煎蛋饭 | 小成就借用正式仪式；一只煎蛋稳稳坐在简洁领奖台中央，饭粒只构成台面的一层。 | 台面的几何、克制的光线；不要加宣判文案或人群。 |
| “想出门，又只想窝在沙发上。” | 可颂三明治 | 可颂的弧线与躺椅椅背呼应；食物保持普通大小，只让影子成为一张躺椅。 | 盘子与光源位置；保持单一投影方向。 |
| “没什么线索，今天就不想多折腾。” | 在中文语境下可先猜一碗热汤面，也允许用户改口 | 温热与安静只作为这次的玩笑猜测；面碗的碗沿接上一小段月台，面条是一条刚停下的轨道。 | 月台边沿、留白、画面温度；不声称用户保守、忧郁或属于某类人格。 |

“想出去玩”可以提高本次尝试新口味的概率，但地点本身不能证明一个人喜欢什么菜。“语气低落”也只能作为这次聊天的轻量假设；优先接住用户已经表达的事实，允许猜错、允许纠正，不把娱乐推测写成心理结论。

## 扩展与审读

### 对用户说话的方式

静态开场、按钮、状态和错误提示已按「说人话」审读。开场用容易接话的日常句子，保留少量轻松联想，不要求用户先编一个有趣答案；句子可以很短，不为字数下限补话。新增开场继续保留稳定 ID。

`play/prompts.mjs` 的 `USER_FACING_VOICE` 是聊天回复和图片配文共用的语气配置。聊天可以有普通、简短的回应；用户换话题就跟着换，问问题就回答，最多追问一个问题，也可以不问。幽默从对方提到的事里来，不要求每轮有反转，不反复绕回口味调查，也不向用户解释情绪分析和线索提取过程。每次实际回复仍由 AI 生成，不使用固定接话脚本。

图片配文只说这张图里的具体关系，可以平静地描述一个荒诞场景，不再补人格判词、劝告或人生感悟。`sceneDescription` 单独描述可见内容供读屏使用。面向用户的语气配置不改变英文视觉字段、食物证据或错配关系要求。

操作提示按实际状态写：停止等待不代表停止服务端绘图，查看已有结果不等于重新出图，打开分享功能也不等于朋友已经收到。达到使用限额时直接说明限额，不用“厨房忙”暗示稍等片刻就能恢复。

### 扩充方向库

新增风格时，先说明主要媒介，再写构形方式；色板和笔触要相互配合。不要用艺术家姓名、模型专用参数或“8K”“masterpiece”等词来代替画法。限制微细节是视觉意图，实际费用仍由模型、尺寸、质量及返回的 usage 决定。

新增错配时，要能回答“哪两个部分接起来了”和“为什么从这次聊天能想到这里”。只是把汉堡和花盆放在同一张桌上，仍然只是并置；汉堡真正借用了花盆的盛放关系，才形成错配。食物应保持可辨认、看起来可以吃，奇怪之处放在容器、比例、结构、功能或场景关系上。

新增气氛时，提供一个可以画出来的表现，例如一个没有解释的微光、一片安静的空场；不要要求同时出现多套天气、时间和光源。“超自然”在这里是温和异象，不自动导向惊吓、血腥或腐烂。

开场句按稳定 ID 维护。新增句子可追加到已有话题末尾或开一个新话题；不要随意重排旧句子，否则本地已读记录会错位。日常、探索、感官、物件、时间与小想象保持分散，不让全部开场都变成口味问卷，也不靠辱骂、人格判断或连续谐音梗制造语气。

## 验证范围

本库可通过 Node 直接导入检查数量、ID 唯一性、开场文本重复、抽样可复现性和未读优先选择。这样的检查只保证材料与接口有效，不能证明生图成功率。错配是否保持可辨认、所选媒介是否压住多余细节，仍需在接通图像 API 后用真实输出验证。
